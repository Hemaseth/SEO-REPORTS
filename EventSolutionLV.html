Start Here — The Convergent Finding
● Flagged independently by five of seven analyses

The Las Vegas migration is unfinished, and identity is split

The same root cause surfaces in Local, Schema, GEO, Content, and SXO independently: geo coordinates 3–4 km off the 89148 street address · sameAs URLs pointing at SF-branded LinkedIn/Facebook/Instagram · four concurrent brand-name variants · all seven team bios describing Bay Area / NY / San Diego backgrounds · /las-vegas-event-planning-services-2/ carrying an H1 of "Las Vegas Event Planning Services" with an H2 of "Experienced Bay Area Event Planning" and a <section class="San Francisco"> block · Person @id resolving to admin while some posts inline author.name: "Joie Nguyen" · Article JSON-LD shipping literal [placeholder] strings on all 16 posts. Treat as one body of work. Most fixes are minutes of configuration. Doing them first lifts Local, Schema, GEO, Content, and SXO at once.

Critical & High Findings
● Critical · Schema · Local

Geo coordinates are 3–4 km off the real address

Schema geo36.1612, -115.2976 ✕ (Summerlin South)
True parcel for 655 S Fort Apache Rd, 89148~36.0862, -115.3025 (Spring Valley)

Google's local pack uses geo for proximity and pin placement. The current pin lands in Summerlin South / Hualapai Way, ~3–4 km north of the 89148 street address. Large enough to suppress the listing for Spring Valley searchers and to flag a structured-data mismatch.

Fix — correct lat/lng on the LocalBusiness block; verify against Google Maps before publishing.
● Critical · Schema · Technical

Homepage is typed as BlogPosting in JSON-LD

Rank Math's "rich snippet" override is misfiring on every non-blog page — homepage, about-us, contact-us, and service pages all carry BlogPosting alongside WebPage. A homepage typed as a blog post is the most semantically incorrect schema instance on the site and forfeits Organization/LocalBusiness rich-result eligibility on the most-linked URL.

Fix — set the homepage Rank Math schema type to WebPage; link LocalBusiness into the @graph via @id; remove BlogPosting override from non-blog page types.
● Critical · Content · Schema · GEO

Author identity is split between admin and "Joie Nguyen"

Some posts (inline author.name)Joie Nguyen
Person @id dereferences to/author/admin/ · "name": "admin"
Twitter card data1 on every page"Written by: admin"
Author archive /author/admin/HTTP 200 · index, follow

Google's structured-data renderer uses @id as authoritative — so even posts that inline "Joie Nguyen" resolve to "admin" in rich-result author attribution. The indexable /author/admin/ archive also leaks the WordPress login username.

Fix — change WordPress display name; migrate the author slug; build an actual /author/joie-nguyen/ bio page with credentials and external sameAs; add jobTitle to the Person node. Confirm the real principal first.
● Critical · Content

No privacy policy or terms — on an active GA4 + contact-form site

/privacy-policy/, /terms/, and /terms-of-service/ all return 404. The site runs GA4 (G-DXW417419P) and contact forms collecting personal data. September 2025 QRG weights Trustworthiness at 30% — the heaviest E-E-A-T factor. CCPA exposure given California-adjacent operations.

Fix — publish privacy policy + terms; link both in the footer. Disclose GA4 data collection at minimum.
● Critical · Content · Schema

Article JSON-LD ships with literal [placeholder] strings

Every blog post's Article schema contains literal [placeholder] text in author.name, image, publisher.logo.url, and mainEntityOfPage.@id. Zero rich-result eligibility for the entire blog. The literal text signals "unpublished-quality work" to any structured-data parser.

Fix — replace placeholder values in the Rank Math Article schema template with real author name, hosted headshot URL, full canonical URL, and organization logo URL.
● Critical · SXO · Content · Local

LV2 page is a Las Vegas URL with San Francisco content

URL/las-vegas-event-planning-services-2/
H1"Las Vegas Event Planning Services"
H2"Experienced Bay Area Event Planning"

The same "Bay Area" H2 also appears on /wedding-concierge/, confirming this is template propagation — not an isolated typo. Google sees a Las Vegas URL with Bay Area H2 content and a San Francisco section class. Neither Las Vegas nor Bay Area signals win. The page dilutes both, and the footer's SF link sends visitors to this LV URL.

Fix — 301 /las-vegas-event-planning-services-2/ → canonical LV services page; remove the "Bay Area" H2 from the surviving page and from /wedding-concierge/; fix the footer SF link target.
● High · GEO · Technical

ModSecurity blocks GPTBot, ClaudeBot, CCBot (HTTP 406)

Block is enforced at the ModSecurity layer — not via robots.txt — so the crawlers receive a hard 406 with no Disallow signal. ChatGPT's browsing pipeline (GPTBot) and Claude.ai retrieval (ClaudeBot) cannot reach the site. OAI-SearchBot passes, so OpenAI's search-specific bot can crawl, but the ChatGPT-Browse pathway is cut off.

Fix — whitelist by UA and reverse-DNS-verify (PTR records in *.gptbot.openai.com, *.anthropic.com); do not disable ModSecurity globally. Declare allow rules in robots.txt for the same UAs to make intent discoverable.
● High · Local · Schema · GEO

sameAs points at the San Francisco sister brand

LinkedInec.linkedin.com/company/event-solutions-san-francisco
Facebookfacebook.com/eventsolutionssf

Google uses sameAs for entity disambiguation. Pointing the Las Vegas LocalBusiness at SF-labeled profiles tells the Knowledge Graph the LV business is the same entity as a San Francisco one — subordinating LV ranking signal to SF and confusing the local pack.

Fix — replace with verified LV-specific profile URLs (LinkedIn / Facebook / Instagram / Yelp). The Rank Math Organization node currently has no sameAs at all — populate it.
● High · Schema · Local

Schema type is generic LocalBusiness

Schema.org defines EventPlanningService as a direct subtype of LocalBusiness > ProfessionalService. Using the parent type forgoes the more specific semantic signal Google uses to match the business to event-planning queries.

Fix — set "@type": ["EventPlanningService", "LocalBusiness"]; add an @id so the block can be cross-referenced from other graph nodes.
● High · Technical · Sitemap

robots.txt has no Sitemap: directive

The 25-byte robots.txt is User-agent: * / Disallow: only. Google can discover the sitemap via Search Console, but Bing, Yandex, and other crawlers relying on robots.txt autodiscovery cannot. One-line fix.

Fix — append Sitemap: https://eventsolutions-lv.com/sitemap_index.xml. Optionally declare explicit AI-crawler Allow rules to make the WAF/robots intent consistent.
